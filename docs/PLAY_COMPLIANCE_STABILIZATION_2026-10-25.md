# UA-Cast: усунення прогалин і стабілізація, 25.10.2026

Цей звіт описує зміни після `PLAY_IP_READINESS_REVIEW_2026-10-25.md`.
Технічні перевірки не є гарантією юридичної відповідності.

## Зміни

- Прибрано вбудований каталог сторонніх EPG і автоматичний fallback. Залишено
  адреси користувача та джерела з його плейлиста. Старі preset IDs більше не
  активують сторонній сервіс; власні збережені URL залишаються. Додано перевірку
  HTTP(S), зрозуміле редагування адреси та можливість вимкнути EPG очищенням поля.
  Після помилки можна повторити завантаження тієї самої адреси без редагування й
  без повторного paywall. Повтор не перетворює автоматично знайдений URL на ручний
  вибір. Зміна провайдера зберігає чинну перевірку Premium.
- EPG не створює новий періодичний стан кожні 30 секунд, коли немає завантаженої
  телепрограми. Повторний запуск ticker не створює дубль. Скасований запит не
  повинен повертати дані після очищення; це перевіряється регресійним тестом.
- Прибрано старі preset API, рядки, невикористаний намальований Cast-подібний
  значок, проміжне меню вибору протоколу та застарілі EPG-записи baseline profile.
  Поле старого формату резервних копій збережено тільки для сумісності JSON.
- Штатний Cast SDK button доступний у плеєрі поруч з окремою кнопкою DLNA.
  На вузьких екранах назва медіа переходить під кнопки. Android TV має окремий
  екран приймача; це не додає sender-кнопки в глобальну навігацію.
- Ліцензії FFmpeg/LGPL, AndroidX/Apache, libyuv, NDK та Roboto відкриваються
  безпосередньо в застосунку через Допомогу й Умови. Великі тексти читаються на IO
  і показуються частинами в LazyColumn. Дозволені лише відомі bundled assets.
- Збережено оригінальні copyright headers; додано повідомлення про модифікації
  JNI/audio/library/renderers та видиме повідомлення FFmpeg.
- Native build працює на Windows і без 8.3 short paths: тимчасові junctions
  забезпечують шляхи без пробілів для GNU make. Тести перевіряють їх очищення
  після успіху й помилки, без видалення цільових каталогів.
- Комплект джерел перевіряється за ZIP checksum, інвентарем файлів, native
  manifest і хешами входів збірки. Signed workflow включає його поряд із APK/AAB.
  Reusable native workflow уже генерував окремий source artifact до цієї зміни;
  виправлено саме зв'язування та перевірку комплекту в signed distribution.
- Підрахунок локальних плейлистів у backup preview замінює вкладений пошук по
  merged sources на набір адрес: O(N+M) замість O(N×M) для цього підрахунку.

## Що залишається перед публікацією застосунку

1. Опублікувати source ZIP саме з відповідною новою версією APK та практично
   перевірити змінену бібліотеку/repack/sign/install. Поточний source ZIP не
   підходить для старих NextLib APK. Під час перевірок 2026-10-25 ADB не бачив
   пристроїв, `emulator -list-avds` повернув порожній список. Повторна перевірка
   2026-10-26 уже бачить Mi TV MSSP2 через ADB; телефона в списку немає.
   Регресія останніх змін на реальному TV/телефоні ще не виконана.
2. Окремо врегулювати історичне розповсюдження GPL-залежності NextLib з фахівцем
   та/або правовласником. Старі релізи не видалялися, власний код не перелiцензовано.
3. Перед Play Console перевірити фінальний listing/screenshots, права на всі
   демонстраційні матеріали, торговельні марки й застосовність патентів на кодеки.
   Походження основної графіки зафіксовано за прямою заявою власника в окремому
   provenance record; це не автоматичне підтвердження всіх можливих прав.
4. Продажі залишаються вимкненими до перевірки статусу видавця, податкових і
   територіальних умов. Рекламний SDK цими змінами не додається.
5. Планове оновлення toolchain/SDK/залежностей: online lint показує підказки
   про нові версії, а R8 повідомляє про недоступність async parsing у provider
   поточної AGP. Масову міграцію AGP/Media3 потрібно окремо перевіряти разом із
   software renderer. Підказки не приховувалися новими suppressions.

Release-compliance gate зберігає незакриті блокування. Публікація юридичних
сторінок не означає випуск нової версії застосунку або підтвердження готовності
Google Play. **Вердикт для релізу поки: NO.**

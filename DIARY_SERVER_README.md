# Персональне зберігання Щоденника

`diary_updated.html` працює офлайн і зберігає дані в браузері. `diary-features.js` додає профіль, статистику, пошук, нагадування, CSV/PDF-експорт і onboarding без важких бібліотек. `manifest.webmanifest` та `sw.js` додають PWA-кеш і встановлення на мобільний пристрій. `diary-server.mjs` — невеликий приватний REST-сервер для синхронізації однієї персональної історії між пристроями.

## Рекомендований варіант для тесту: Firebase + GitHub Pages

GitHub Pages віддає статичні файли, тому для реєстрації та хмарних даних використовується Firebase Authentication + Cloud Firestore. У Firebase Console:

1. Створи проєкт і додай Web app.
2. У Authentication → Sign-in method увімкни Email/Password.
3. Створи Firestore Database у production mode.
4. Опублікуй вміст `firestore.rules` у Rules і натисни Publish.
5. Скопіюй web config у `firebase-config.js`. Цей config можна публікувати, але Admin SDK private key — ніколи.
6. У Authentication → Settings → Authorized domains додай адресу GitHub Pages (`username.github.io`) і `localhost` для локального тесту.

Після цього кнопка «Вхід / реєстрація» з’явиться у щоденнику. Дані кожного користувача зберігаються у власному Firestore-шляху `users/{uid}/diary/main`, а правила не дозволяють читати чужі записи.

Профільні налаштування, тема, часовий пояс і параметри нагадувань зберігаються разом із cloud-документом. Нагадування в браузері працюють після надання дозволу; для повністю автономних push-сповіщень потрібне окреме FCM/Web Push налаштування.

Для GitHub Pages створи public repository на GitHub Free, поклади файли з цієї папки в root і зроби push у `main`. Workflow `.github/workflows/pages.yml` автоматично опублікує сайт. Відкрий Settings → Pages і вибери GitHub Actions як джерело. `index.html` переадресує на щоденник.

Перед push перевір, що у репозиторії немає `diary-data.json`, `.bak` або Firebase Admin private key. Публічний Firebase web config сам по собі не захищає дані — їх захищають Authentication і Firestore Rules.

## Безпечний локальний запуск

Потрібен Node.js 18 або новіший. У папці з файлами:

```powershell
$env:DIARY_TOKEN = "зміни-цей-довгий-випадковий-токен"
$env:DIARY_ORIGIN = "http://localhost:8787"
node diary-server.mjs
```

Після запуску відкрий `http://localhost:8787`. Сервер автоматично створить `diary-data.json` під час першого запису. Копія попередньої версії зберігається у `diary-data.json.bak`.

Для суто локального тесту без ключа можна явно використати `$env:DIARY_DEV_MODE = "1"`. Не використовуй цей режим на публічному хостингу.

У застосунку відкрий «Синхронізація» і вкажи:

```text
http://localhost:8787/api/diary
```

У поле «Ключ доступу» введи те саме значення, що й у `DIARY_TOKEN`. Ключ зберігається лише в сесії браузера і ніколи не записується у щоденник або на сервер разом із даними.

## Робота з різних пристроїв

Перший пристрій створює сховище й завантажує туди локальні записи. На іншому телефоні або ноутбуці відкрий ту саму адресу застосунку, введи endpoint і той самий ключ — історія завантажиться із сервера. Нові записи синхронізуються автоматично; при одночасній зміні на двох пристроях сервер повертає конфлікт і не перетирає новішу версію мовчки. У налаштуваннях можна зафіксувати часовий пояс, щоб дата «сьогодні» не змінювалася під час подорожі.

Для доступу з іншої країни потрібен публічний домен із HTTPS і reverse proxy (наприклад, Nginx/Caddy), який передає запити до локального Node-процесу. Країна перебування пристрою не має значення, якщо є інтернет і сервер доступний.

## Налаштування

- `DIARY_PORT` — порт, за замовчуванням `8787`.
- `DIARY_HOST` — адреса прослуховування, за замовчуванням `127.0.0.1`; для reverse proxy цього достатньо.
- `DIARY_TOKEN` — обов’язковий Bearer-токен для приватного доступу.
- `DIARY_ORIGIN` — точний origin фронтенду, наприклад `https://diary.example.com`; wildcard `*` не використовується.
- `DIARY_DATA_FILE` — шлях до JSON-файлу бази.

Сервер має захист заголовками, обмеження розміру JSON, базову перевірку схеми, обмеження невдалих авторизацій, атомарний запис і версії даних. Для публічного використання все одно потрібні HTTPS, firewall, резервне копіювання файлу та регулярне оновлення Node.js.

Це одноосібне персональне сховище, а не багатокористувацька система з акаунтами. Не коміть `diary-data.json`, `.bak` або секрет токена в Git.
